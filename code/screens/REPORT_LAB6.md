# Отчёт по лабораторной работе №6

**Тема:** Улучшение пользовательского опыта (UX) разрабатываемого ПО  
**Проект:** KitchenMate (Python, Tkinter, SQLite)

---

## 1. Введение и цели работы

Цель работы — провести **UX-аудит** десктопного приложения KitchenMate, выявить проблемные зоны по атрибутам **Usability** (ISO/IEC 25010:2011), спроектировать не менее трёх улучшений, **реализовать их в коде** и подтвердить часть требований **скриптом автоматической проверки** (адаптация идеи WCAG/HTML-проверок к исходникам Tkinter).

Ограничение платформы: у **Tkinter** нет DOM и `aria-*`, как в веб-интерфейсе; доступность обеспечивается **текстовыми подписями**, **предсказуемой навигацией с клавиатуры** на форме входа и **явными подтверждениями** деструктивных действий.

| Атрибут | До | После | Краткое обоснование |
|--------|-----|--------|---------------------|
| **Распознаваемость соответствия** | 4/5 | 4/5 | Назначение экранов понятно по заголовкам («Кладовая», «Список покупок»); изменения не меняли структуру IA. |
| **Обучаемость** | 3/5 | 5/5 | Добавлены **empty states** с подсказкой следующего шага при пустой кладовой, пустом списке покупок и пустом избранном. |
| **Операбельность** | 3/5 | 5/5 | На экране входа: **Enter** в поле пароля отправляет форму; Tab-цепочка логична (логин → пароль → кнопки). |
| **Защита от ошибок** | 3/5 | 5/5 | Удаление продуктов/позиций/избранного — через **кастомное модальное окно** с нейтральной «Отмена» и красной деструктивной кнопкой, вместо однотипного системного `messagebox.askyesno`. |
| **Эстетика GUI** | 4/5 | 5/5 | Пустые состояния оформлены карточкой с рамкой акцентного цвета и мягким фоном `SOFT_GREEN`; диалоги согласованы с палитрой проекта. |
| **Доступность** | 2/5 | 4/5 | Текстовые метки у полей входа; кнопки **«Удалить»** вместо одной иконки «❌»; кнопка **«Удалить из избранного»** вместо неозвучиваемого символа «♥». Добавлены **клавиатурные shortcuts** (Enter для подтверждения, Escape для очистки полей) и **визуальная подсветка ингредиентов** в рецептах (зелёный — есть в кладовой, красный — нет). Полноценный WCAG для Tk не достигается без платформенных API — зафиксировано как ограничение. |

## 4. Три реализованных улучшения («До» vs «После»)

### 4.1. Кастомное подтверждение деструктивных действий

- **Проблема:** Стандартный `messagebox` выглядит как системный диалог Windows, не отражает акцент «опасного» действия и слабее по UX-паттернам подтверждения удаления.
- **Решение:** Модуль `code/ui_helpers.py`, функция `confirm_destructive()` — модальное окно с текстом, пояснением и кнопками **Отмена** / **Удалить** (красная).
- **Интеграция:** `pantry_screen.py` (удаление продукта), `shopping_screen.py` (удаление строки), `favorites_screen.py` (удаление из избранного).

### 4.2. Empty state (пустые состояния)

- **Проблема:** Пустой список без пояснения повышает когнитивную нагрузку («сломалось или нужно что-то нажать?»).
- **Решение:** Блоки с рамкой и текстом-подсказкой в **кладовой**, **списке покупок**, **избранном** при `len(items)==0` / `len(favorites)==0`.

### 4.3. Клавиатура и понятные подписи на элементах управления

- **Проблема:** Вход только мышью; кнопка «❌» и иконка «♥» плохо интерпретируются без контекста (в т.ч. при использовании средств чтения с экрана в рамках возможностей ОС).
- **Решение:** `login_screen.py` — фокус в поле логина при открытии, **Enter** в пароле вызывает вход; кнопки удаления с текстом **«Удалить»**, **«Удалить из избранного»**.

### 4.4. Визуальная подсветка ингредиентов и расширенные клавиатурные shortcuts

- **Проблема:** Пользователи не видят, какие ингредиенты у них есть, что приводит к неэффективному планированию покупок; ограниченная поддержка клавиатуры снижает доступность для пользователей с моторными ограничениями.
- **Решение:** В деталях рецепта ингредиенты подсвечиваются **зелёным** (есть в кладовой) или **красным** (нет); кнопка добавляет отсутствующие ингредиенты напрямую в кладовую. Расширены shortcuts: **Enter** для подтверждения действий во всех полях ввода, **Escape** для быстрой очистки полей.
- **Интеграция:** `main.py` (show_recipe_details), `screens/pantry_screen.py`, `screens/shopping_screen.py`, `screens/main_screen.py`, `screens/add_recipe_screen.py`.

**Сравнительный анализ (скриншоты):** вставьте в сдаваемый документ **2 скриншота** на каждое улучшение (экран/диалог «до» из истории Git и «после» из текущей версии) или снимки текущего состояния с подписью «после внедрения».

## 5. Wireframes (черновые схемы до кодирования)

**Empty state — кладовая (вид сверху):**

```
+------------------------------------------+
|  Моя кладовая                            |
+------------------------------------------+
|  +------------------------------------+  |
|  | Пока нет продуктов                 |  |
|  | Добавьте первый продукт в форме   |  |
|  | ниже ...                           |  |
|  +------------------------------------+  |
|  [ Название: ____ ] [ Кол-во: ___ ] [+]  |
+------------------------------------------+
```

**Кастомное подтверждение удаления:**

```
+--------------------------------+
| Удаление продукта              |
| Удалить «Сыр» из кладовой?     |
| Это действие нельзя отменить.  |
|              [ Удалить ] [Отмена]|
+--------------------------------+
```

## 6. Скрипт автоматизации / проверки

**Назначение:** статический анализ репозитория (не E2E в браузере): наличие `ui_helpers.confirm_destructive`, меток полей входа, привязки Enter, отсутствие «пустых» текстов кнопок, базовый контраст цветов из `config.py` на белом фоне.

**Файл:** `scripts/ux_accessibility_check.py`

**Запуск из корня репозитория:**

```bash
python3 scripts/ux_accessibility_check.py
```

**Пример успешного вывода:**

```
KitchenMate — UX / accessibility static check
==================================================
Status: PASS
Замечаний по выбранным правилам не найдено.
```

При нарушении правил скрипт завершается с кодом **1** и печатает список замечаний (удобно для CI).

**Скриншот для отчёта:** сделайте снимок терминала с командой и выводом `Status: PASS`.

## 8. Вывод

Проведённые изменения напрямую улучшают атрибуты **обучаемости**, **операбельности**, **защиты от ошибок** и **эстетики** за счёт осмысленных пустых состояний и согласованных диалогов. **Доступность** повышена за счёт текстовых подписей, клавиатурного сценария входа, визуальной подсветки ингредиентов и расширенных shortcuts (Enter/Escape). Для десктопного Tkinter остаётся ограничение по сравнению с WCAG для веба. Скрипт `ux_accessibility_check.py` даёт воспроизводимую проверку выбранных правил при каждом изменении UI.
